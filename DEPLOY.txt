Tenerife Travel — публикация v62

Для текущей демонстрации собственный домен и SEO-настройки не обязательны.
Достаточно бесплатного адреса хостинга.

Простой вариант без Git: Cloudflare Pages Direct Upload.
В панели Cloudflare открыть Workers & Pages, затем Create application,
Get started и Drag and drop your files. Указать имя проекта, загрузить
готовый release ZIP и нажать Deploy site. Получится адрес <имя>.pages.dev.
Инструкция: https://developers.cloudflare.com/pages/get-started/direct-upload/

Если остаётесь на Render: создать именно Static Site, подключить репозиторий
с src/ и build.py, команда сборки python build.py, Publish Directory: dist.
Static Site обслуживается CDN и не использует засыпающий бесплатный Web Service.
Инструкция: https://render.com/docs/static-sites

1. Подготовить архив

Из папки E:\tenerife-travel выполнить:
    python tools/prepare_release.py

Нужны Python 3.10+ и Node.js для проверок; устанавливать npm-пакеты не нужно.
Команда собирает сайт, проверяет сценарии прокрутки, JavaScript, файлы и якоря,
затем создаёт новый ZIP в releases/. Ничего не публикуется автоматически.
Рядом лежит список SHA-256 файлов для проверки состава выпуска.

2. Загрузить сайт

Загрузить содержимое ZIP на статический хостинг. В корне публикации должны
лежать index.html, site.<hash>.css, site.<hash>.js и папка assets/.
Если хостинг принимает ZIP, выбрать этот архив. Если принимает папку —
распаковать архив и выбрать получившуюся папку.
Исходники src/, backups/, tools/ и весь проект загружать не нужно.
Для хостинга со сборкой команда: python build.py; каталог публикации: dist.
В dist/ может оставаться локальная рамка preview.html; release ZIP её исключает.

3. После выбора хостинга и домена

Подключить домен и HTTPS средствами хостинга. Определить основной адрес
(с www или без) и перенаправить альтернативный адрес на основной.
Добавить canonical, og:url, абсолютный адрес картинки превью и sitemap
с реальным доменом. Не подставлять временный или выдуманный адрес.

HTML должен проверяться на обновления (Cache-Control: no-cache).
Файлы site.<hash>.css/js можно кешировать надолго с immutable.
Файлы assets/ имеют постоянные имена: не задавать им годовой immutable-кеш
без изменения имён при замене содержимого. Конкретная настройка зависит
от хостинга. Желательно использовать его атомарные публикации/откаты.

4. Проверка опубликованной версии

Открыть HTTPS-адрес на компьютере и настоящем телефоне. Проверить первый экран,
прокрутку туда и обратно, языки, выбор поездки и переход в форму.
Проверить рабочие контакты, ссылки соцсетей и текст WhatsApp до отправки.
Проверить загрузку фотографий/шрифтов и отсутствие ошибок или пропавших файлов.
Форма не хранит заявки: посетитель отправляет подготовленный текст в WhatsApp.

5. Откат

Перед изменением кнопок и свайпов сохранена принятая версия v61:
    backups/before-interface-v62.zip
Готовый ZIP выпуска v61 также остаётся в releases/.

Перед облегчением мобильных анимаций сохранена версия v60:
    backups/before-mobile-motion-v61.zip
Перед адаптивной компоновкой сохранена версия v59:
    backups/before-responsive-trial-v60.zip
Эти резервные архивы не предназначены для прямой загрузки на хостинг.
Порядок восстановления исходников описан в README.md.
После запуска сохранять каждый выпущенный ZIP и пользоваться откатом
хостинга к предыдущей публикации либо повторно загружать прежний release ZIP.
